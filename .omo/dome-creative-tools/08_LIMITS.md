## HARD LIMITS

| Limit | Category | Reason | Consequence |
|-------|----------|--------|-------------|
| No server-side processing | Architecture | GitHub Pages is static-only | All processing must be client-side (Canvas, Web Audio, wasm) |
| No backend secrets in client code | Security | Browser code is public | Firebase config is public by design; security via Firebase Rules, not hidden keys |
| Max 1GB Pages artifact | Deployment | GitHub Pages limit | Bundle must stay under 1GB; ffmpeg.wasm loaded dynamically |
| Audio requires user gesture | Browser Policy | Autoplay Policy / Web Audio API | AudioContext must be created/resumed after user click, not on page load |
| No localStorage/sessionStorage in sandboxed contexts | Browser Security | Sandboxed iframes block storage | Use in-memory state or Firebase for persistence |
| No BrowserRouter | Routing | GitHub Pages serves static files, no server rewrite | Must use HashRouter to avoid 404 on refresh |
| Vite base must be /tools/ | Build Config | App served at subpath of DOME | Without correct base, assets load from wrong path |
| VITE_ prefix required for env vars | Build Config | Vite only exposes VITE_-prefixed vars to client | Firebase config must use VITE_FIREBASE_* naming |

## SOFT LIMITS

| Limit | Category | Reason | Mitigation |
|-------|----------|--------|------------|
| Mobile memory for wasm | Performance | ffmpeg.wasm uses ~100-200MB | Show warning on mobile, recommend desktop |
| Canvas performance on mobile | Performance | Mobile GPUs weaker | Lower resolution, fewer particles, frame rate cap |
| Firebase Spark write limit | Data | 10K writes/day | Only relevant for presets (P3); cache locally, batch writes |
| File size for upload | UX | Large files crash browser | Validate client-side, max 50MB warning, reject >100MB |
| Bundle size for initial load | Performance | Users wait for JS to download | Code-split each tool with React.lazy, only load what's clicked |

## ANTI-PATTERNS (must not do)

- Do NOT create AudioContext on page load — browsers block it without user gesture
- Do NOT use BrowserRouter — 404 on refresh in GitHub Pages
- Do NOT bundle ffmpeg.wasm in the main chunk — it's 30MB+, load dynamically with `import()`
- Do NOT assume Firebase is available — tools must work without Firebase (graceful degradation)
- Do NOT put Firebase secrets in the repo — use GitHub Environments + Actions env injection
- Do NOT use localStorage for tool state — sandboxed iframes block it; use in-memory or Firebase
- Do NOT skip the `base` config in Vite — assets will 404 on Pages
